cada cliente logado segura uma conexão pela sessão inteira, então isto é o mais perto de "gente conectada" que o processo sabe. o pico é exato, não amostrado: ele é medido toda vez que uma conexão abre.

pool do postgres

em uso — —
na fila — pedidos esperando conexão
pico na fila — —

fila acima de zero é o aviso mais cedo que este sistema consegue dar: nada quebra, nada fica lento o suficiente para reclamar, e mesmo assim já tem pedido esperando conexão. mas fila sozinha não quer dizer pool esgotado — o pg enfileira sempre que não consegue entregar uma conexão no mesmo tick, inclusive enquanto ainda está abrindo as primeiras. o teto de verdade é fila com o pool cheio, e depois do fato quem conta isso é o pico em uso ter chegado no máximo. o pico da fila é observado na hora em que uma conexão é entregue: ele nunca exagera e pode ficar um pouco abaixo do real.

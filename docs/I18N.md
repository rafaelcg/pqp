# i18n

pqp uses **i18next core** in the web client and in the Electron main process.
Do not add `react-i18next`. Components import only `@/lib/i18n`. Transports
import `translateMessage` from that same module.

English is the source of truth. Missing Portuguese falls back to English, never
to a raw key.

## Add a string

1. Put the English sentence in `client/src/locales/en/translation.json`.
2. Put the Portuguese sentence in `client/src/locales/pt-BR/translation.json`.
3. Call `t("dotted.key")` or `translateMessage("dotted.key")`.
4. Keys are flat dotted literals. `keySeparator` is false, so `t("memberList.title")` is one key, not nested JSON.

Interpolation uses single braces: `{name}`, not `{{name}}`.

```ts
t("composer.placeholder", { name: channel.name });
```

## Plurals

Use i18next suffixes, not `.one` / `.many`:

- `invite.uses.unlimited_one`
- `invite.uses.unlimited_other`
- `invite.uses.unlimited_zero` when 0 must not use the Portuguese singular

Call the **base** key with a numeric `count`:

```ts
t("invite.uses.unlimited", { count });
```

`count` must be a finite number. Formatted display uses a second var (`countLabel`).

Portuguese CLDR treats 0 as `one`. "0 usos" needs `_zero` or the UI will print "0 uso".

Typing lines are not CLDR. Pick the key at the call site: `chat.typing_one` / `_two` / `_other`.

SSO copy is a select, not a plural: `sso.body_single` / `sso.body_several`.

Do not combine `_desktop` with plurals.

## Desktop context

Pass `{ context: "desktop" }` only at permission call sites. The wrapper does not inject it.

```ts
t("voice.error.micBlocked", desktopContext());
```

Electron menus never say "navegador" or "browser".

## Boot and switch

English loads synchronously. Portuguese is a dynamic import. An English-first paint is accepted. Never statically import the pt-BR JSON from `instance.ts`.

Language switch still reloads. `?lang=` outranks `localStorage` and Electron's `userData/locale.json`.

## Electron

Menu and updater strings live in `electron/locales/`, a separate i18next instance.
`extraResources` copies that folder. Packaged renderer strings come from the CDN.
Menu strings come from the binary. They can skew until the next shell release.

`role:` submenu items may follow the OS language.

## Import rules

- Import `@/lib/i18n` from app code.
- Import `i18next` only inside `client/src/lib/i18n/` and `electron/`.
- Never import `react-i18next`.
- Cloudflare Pages OG middleware (`profile-meta.ts`, `community-meta.ts`, `client/functions/_middleware.ts`) stays out of i18next.
- iOS catalogue stays separate.
- `error-boundary.tsx` stays English.

## Bundle

i18next 26 ESM gzip is about 18 kB. The old custom catalogue veto in `catalogue.ts` is gone. Lazy pt-BR still keeps Portuguese out of the English main chunk.

## Glossary (chrome)

Você-imperative on settings, menus, errors, and destructive actions. First-run, onboarding, and marketing keep spoken voice.

Loanwords stay. The QG says them in English. Translating them is what sounds like a model.

Keep: chat, call, mute / mutar, kick / kickar, ban, DM, staff, post, feed, login, app, APK, VIP, card, thread, self-host, mesh, SFU, open source (as a label), Watch party, Chrome, Play Store, TestFlight. Offline and Online stay English.

Do not keep English the chrome already translated: rail → barra, pin → fixar, settings → Configurações. Copy the pt-BR button when you name it.

QG replies, What's New, and any PT-BR a person will read in the channel follow `AGENTS.md` § PT-BR voice. Write Portuguese first. Do not translate the English. Do not translate the loanwords either.

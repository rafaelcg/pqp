# Invite links, and the one exception under /app. This is not permission to
# index them — the edge middleware writes `noindex, nofollow` into every one of
# these pages (see client/src/lib/invite-meta.ts). It is permission to FETCH
# them, which is a different thing and the one that matters: an unfurler has to
# read the bytes to draw a card, and the bots that respect this file (Twitter's
# among them) were refusing to, so a pasted invite showed no preview at all on
# those platforms. Allowing the fetch is also what lets Google see the
# `noindex` and drop the URL outright, which a blanket Disallow cannot do — a
# disallowed URL can still be listed from links alone.
#
# It costs nothing to allow: the page is the SPA shell behind a login, joining
# is an authenticated POST, and no crawler can consume an invite by loading it.
# The Allow comes first so that both longest-match parsers and naive
# first-match ones agree.
Allow: /app/invite/

# The rest of /app used to be `Disallow: /app`. Dropped on purpose: every URL
# under it is per-account and behind a login, so nothing there was ever going
# to rank, but a `Disallow` only stops a crawler that discovers the URL by
# crawling. One handed the URL directly (an old share, a pasted link) indexes
# it anyway with no title and no description, because a directive a crawler
# never fetches is a directive it never reads — Search Console's own name for
# that is "Indexed, though blocked by robots.txt", and it was happening to
# `/app/server/<id>` pages that nobody could see behind. The fix is the other
# way around: the crawl is allowed through (by `Allow: /` above), and the edge
# middleware answers every `/app/*` request except `/app/invite/` with
# `X-Robots-Tag: noindex, nofollow` (see client/src/lib/app-robots.ts) — a
# header a crawler reads before it parses a single byte of the sign-in screen
# it would otherwise index.

# Public images live under /api, and this file is served on api.pqp.gg too,
# where /api is the real API. A profile's og:image is its avatar at
# /api/avatars/<id>, and profile and community banners sit under /api as well,
# so an unfurler or Google that respects this file has to be allowed to FETCH
# them or a shared card shows no picture. These routes are public and
# unauthenticated by design (the public-route list in server/src/api). Allow
# comes first so a longest-match parser lets the image through while the rest
# of /api stays fenced below. The avatar path is a plain prefix every parser
# honours; the banner paths use a wildcard Google honours and others fall back
# to the fence on, which is no worse than today.
Allow: /api/avatars/
Allow: /api/users/*/banner
Allow: /api/servers/*/banner

# There is no API on this host (it lives on api.pqp.gg), so this is a fence
# against a crawler that guesses; it costs nothing and reads as intended.
Disallow: /api

# Content Signals (contentsignals.org, draft-romm-aipref-contentsignals). What
# this site is willing to be used for by whoever fetches it. Search and
# answering a question from a fetched page are fine, that is how a public
# profile or a release note gets found. Training is not: most of what is public
# here is other people's words and pictures on their own pages, and it is not
# ours to hand over as a corpus. One line to flip if that changes.
Content-Signal: search=yes, ai-input=yes, ai-train=no
